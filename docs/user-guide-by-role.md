# คู่มือการใช้งาน Haris Payroll แยกตามบทบาท

เอกสารนี้อธิบายหน้าเว็บและสิทธิ์ที่มีอยู่จริงบน branch `develop` ณ วันที่
30 กันยายน 2026 สำหรับ 5 บทบาท ได้แก่ Employee, Supervisor, Branch Manager,
HR และ Owner

> สิทธิ์จริงตรวจโดย backend ทุกครั้ง เมนูที่ถูกซ่อนเป็นเพียงการช่วยลดความสับสน
> ไม่ใช่กลไกความปลอดภัย หากเปิด URL โดยตรงแต่ไม่มีสิทธิ์ ระบบต้องปฏิเสธคำขอ

## 1. เริ่มต้นใช้งาน

### 1.1 เข้าสู่ระบบ

1. เปิดหน้า `/login`.
2. กรอก **ชื่อผู้ใช้** และ **รหัสผ่าน** ที่ Owner หรือ HR จัดเตรียมให้.
3. กด **เข้าสู่พื้นที่ทำงาน**.
4. ระบบจะแสดงเฉพาะเมนูที่บทบาทปัจจุบันใช้งานได้.

ข้อจำกัดปัจจุบัน: หลังเข้าสู่ระบบ ทุกบทบาทถูกส่งไปหน้า Payroll ก่อน ผู้ใช้ที่
ไม่มีสิทธิ์ Payroll อาจเห็นหน้าแจ้งว่าไม่มีสิทธิ์ ให้เปิดเมนูหลักแล้วเลือก
**ภาพรวม** หรืองานที่ตนมีสิทธิ์ ปัญหานี้ติดตามใน completion plan T028

หากกรอกรหัสผ่านผิดหลายครั้ง บัญชีจะถูกล็อกชั่วคราวตามค่าที่ผู้ดูแลระบบกำหนด
อย่าลองซ้ำต่อเนื่อง ให้รอจนครบช่วงล็อกหรือติดต่อ Owner/HR เพื่อปลดล็อกหรือ
รีเซ็ตรหัสผ่าน

รหัสผ่านชั่วคราวจากการสร้างหรือรีเซ็ตบัญชีจะแสดงแก่ผู้ดูแลเพียงครั้งเดียว
ระบบยังไม่มีหน้าสำหรับผู้ใช้เปลี่ยนรหัสผ่านด้วยตนเอง จึงต้องจัดการรหัสชั่วคราว
ตามนโยบายภายในจนกว่างาน T022 ใน completion plan จะเสร็จ

### 1.2 เมนูบนคอมพิวเตอร์และโทรศัพท์

- คอมพิวเตอร์: เมนูอยู่ด้านซ้าย.
- โทรศัพท์หรือหน้าจอแคบ: กด **เปิดเมนูหลัก** ที่ด้านบน.
- ชื่อบัญชีปัจจุบันแสดงที่ส่วนหัว.
- กด **ออกจากระบบ** เมื่อใช้งานเสร็จ โดยเฉพาะเครื่องที่ใช้ร่วมกัน.

### 1.3 ความหมายของสถานะสำคัญ

- **รอพิจารณา**: ยังแก้ไขหรือพิจารณาได้ตามสิทธิ์.
- **อนุมัติแล้ว / ไม่อนุมัติ**: เป็นผลการตัดสินที่บันทึกเป็นประวัติแล้ว.
- **ฉบับร่าง**: รอบเงินเดือนยังแก้ข้อมูลต้นทางและคำนวณใหม่ได้.
- **คำนวณแล้ว**: มีผล preview ล่าสุด แต่ยังไม่ตรึงข้อมูล.
- **ล็อกแล้ว**: ห้ามแก้ค่าที่ใช้คำนวณย้อนหลัง ต้องใช้ Adjustment.
- **ยกเลิกสลิป**: เก็บสลิปและประวัติการส่งเดิมไว้ แต่ไม่ควรนำไปใช้งานต่อ.

### 1.4 เมื่อระบบทำรายการไม่สำเร็จ

1. อ่านข้อความเหตุผลก่อนกดซ้ำ เช่น ไม่มีสิทธิ์, ข้อมูลซ้ำ, รอบถูกล็อก หรือ
   ข้อมูลเงินเดือนยังไม่ครบ.
2. จด **Request ID** หากหน้าจอแสดงค่า เพื่อให้ผู้ดูแลค้นใน Audit ได้.
3. อย่าสร้างรายการใหม่เพื่อหลบ error หากรายการเดิมมีผลทางประวัติ.
4. หากเป็นข้อมูลที่ล็อกแล้ว ให้ใช้กระบวนการ Adjustment หรือแจ้ง HR.

## 3. คู่มือ Employee

### 3.1 ดูข้อมูลของตนเอง

1. เปิด **พนักงาน**.
2. ระบบควรแสดงเฉพาะข้อมูลที่เชื่อมกับบัญชีของตนเอง.
3. เปิดรายละเอียดเพื่อดูข้อมูลการทำงานและข้อมูลติดต่อที่ได้รับอนุญาต.
4. หน้า Employment, Bank และ Weekly Holidays จะแสดงข้อมูลตามสิทธิ์ โดยเลขบัญชี
   ธนาคารต้องถูกปกปิดและผู้ใช้คนอื่นต้องไม่เห็นข้อมูลส่วนตัวนี้.

หากเห็นข้อมูลของบุคคลอื่น ให้หยุดใช้งานหน้านั้นและแจ้ง Owner/HR ทันที

### 3.2 ส่งคำขอลา

1. เปิด **การลา**.
2. ส่วนพนักงานต้องแสดงชื่อของตนเองและไม่มีช่องเลือกพนักงานอื่น.
3. เลือก **ประเภทการลา**, วันที่เริ่ม, วันที่สิ้นสุด และกรอกเหตุผล.
4. เลือก **คำขอย้อนหลัง** เฉพาะเมื่อเป็นเหตุการณ์ย้อนหลังจริง.
5. กด **ส่งคำขอ**.
6. ตรวจว่าสถานะใหม่เป็น **รอพิจารณา**.

การแก้คำขอ:

1. โหลดรายการของตนเอง.
2. ที่คำขอสถานะรอพิจารณา กด **แก้ไขคำขอ**.
3. แก้ประเภท วันที่ หรือเหตุผล แล้วกด **บันทึกการแก้ไข**.
4. คำขอที่พิจารณาแล้วแก้ผ่านหน้าปกติไม่ได้ ให้ติดต่อ HR.

ข้อจำกัดปัจจุบัน: ประเภทลาที่กำหนดว่าต้องมีเอกสารจะแสดงข้อความเตือน แต่ระบบ
แนบเอกสารยังไม่เปิดใช้งาน

### 3.3 ส่งคำขอทำงานล่วงเวลา

1. เปิด **ทำงานล่วงเวลา**.
2. เลือกประเภท:
   - **รายชั่วโมง** แล้วกรอกจำนวนชั่วโมง.
   - **วันหยุดประจำสัปดาห์** แล้วกรอกจำนวนวัน.
   - **วันหยุดนักขัตฤกษ์** แล้วกรอกจำนวนวัน.
3. กรอกวันที่ เหตุผล และรายการลงเวลาอ้างอิงถ้ามี.
4. กด **ส่งคำขอ**.
5. ตรวจว่าสถานะเป็น **รอพิจารณา**.

การออกงานสายกว่าปกติไม่ทำให้เกิด OT ที่จ่ายเงินโดยอัตโนมัติ เฉพาะรายการที่
ผู้มีสิทธิ์อนุมัติแล้วเท่านั้นจึงถูกนำไปคำนวณเงินเดือน

### 3.4 ดูสลิปเงินเดือน

1. เปิด **สลิปเงินเดือน**.
2. ระบบโหลดเฉพาะสลิปที่เชื่อมกับ employee record ของบัญชีนี้.
3. ตรวจวันที่ออกสลิป รายได้ รายการหัก และยอดสุทธิ.

ปัจจุบันหน้า Employee แสดงรายการสรุป ยังไม่มีหน้าเปิดรายละเอียดหรือดาวน์โหลด
สลิปแบบ printable งานนี้อยู่ใน completion plan T020

### 3.5 สิ่งที่ Employee ยังทำไม่ได้ผ่านเว็บ

- ดูหรือแก้ Attendance.
- ขอเงินทดรองผ่านหน้า Finance แม้ backend รองรับ self-scope แล้ว.
- ดู Payroll workspace, Reports หรือ Audit.
- เปิดข้อมูลพนักงานคนอื่น.
- แนบเอกสารประกอบการลา.

## 4. คู่มือ Supervisor

Supervisor ทำงานภายใน **แผนกและสาขาที่ระบุใน role grant** เท่านั้น

### 4.1 ดูทีมในแผนก

1. เปิด **พนักงาน**.
2. ค้นหาด้วยชื่อ รหัสพนักงาน หรือข้อมูลที่หน้าจอรองรับ.
3. ระบบต้องคืนเฉพาะพนักงานที่มี assignment ในแผนกของ Supervisor ณ วันที่ที่
   เกี่ยวข้อง.
4. ข้อมูลเงินเดือน เลขประจำตัวเต็ม และบัญชีธนาคารต้องไม่ถูกเปิดเผย.

### 4.2 ตรวจและบันทึก Attendance

1. เปิด **ลงเวลา**.
2. เลือกพนักงานในขอบเขตของตนเอง.
3. เลือกช่วงวันที่ แล้วกด **โหลดรายการ**.
4. ตรวจวันที่ สาขา สถานะ เวลาเข้า/ออก นาทีสาย การหักเงิน และแหล่งที่มา.
5. หากยังไม่มีรายการ ใช้แบบฟอร์ม **บันทึกวันทำงาน**:
   - ระบุสาขาและวันที่.
   - เลือกสถานะ เช่น มาทำงาน, มาสาย, ขาดงาน หรือวันหยุด.
   - กรอกเวลาเข้า/ออกและนาทีสายเมื่อเกี่ยวข้อง.
   - เลือก **หักเงิน** เฉพาะตามนโยบาย.
6. หากข้อมูลผิด ใช้ **แก้ไขรายการ**, เลือกรายการเดิมและกรอกเหตุผล.

ระบบจะปฏิเสธการแก้ข้อมูลที่อยู่ในรอบเงินเดือนซึ่งล็อกแล้ว

### 4.3 พิจารณาการลา

1. เปิด **การลา** และเลือกพนักงานในแผนก.
2. กด **โหลดคำขอ**.
3. ตรวจประเภทลา วันที่ จำนวนวัน และเหตุผล.
4. สำหรับคำขอไม่เกิน 3 วัน:
   - เลือกประเภทสุดท้ายหากต้องแก้ประเภท.
   - กรอกหมายเหตุ.
   - กด **อนุมัติ** หรือ **ไม่อนุมัติ**.
5. คำขอเกิน 3 วันต้องส่งต่อ Branch Manager; backend ต้องปฏิเสธหาก Supervisor
   พยายามอนุมัติเอง.

### 4.4 พิจารณา OT

1. เปิด **ทำงานล่วงเวลา** และเลือกพนักงานในแผนก.
2. โหลดคำขอและตรวจวันที่ ประเภท ชั่วโมง/วัน และเหตุผล.
3. กรอกหมายเหตุ แล้วกด **อนุมัติ** หรือ **ไม่อนุมัติ**.
4. รายการที่ตัดสินแล้วแก้ทับไม่ได้ หากต้องแก้ให้ HR ดำเนินการตามกระบวนการที่
   บันทึกประวัติได้.

### 4.5 ข้อจำกัดของ Supervisor

- ไม่มีสิทธิ์ Finance, Payroll, Payslip administration, Reports, Audit,
  Organization หรือ Accounts.
- ไม่เห็นพนักงานนอกแผนก.
- ไม่อนุมัติการลาเกิน 3 วัน.
- หน้า Schedule/Holiday management ยังไม่ถูกเปิดในเมนู.

## 5. คู่มือ Branch Manager

Branch Manager ทำงานภายใน **สาขาที่ระบุใน role grant**

### 5.1 จัดการพนักงานและ Attendance ในสาขา

ใช้ขั้นตอนเดียวกับ Supervisor แต่ขอบเขตเป็นทั้งสาขา ระบบต้องไม่คืนพนักงานหรือ
Attendance จากสาขาอื่น

### 5.2 พิจารณาการลาและ OT

- เลือกพนักงานในสาขาและโหลดคำขอ.
- Branch Manager อนุมัติคำขอลาได้ทุกจำนวนวันภายในสาขา รวมถึงคำขอ 4 วันขึ้นไป.
- สามารถอนุมัติหรือไม่อนุมัติ OT ภายในสาขา.
- การพิจารณาทุกครั้งต้องถูกเก็บใน approval history.

### 5.3 ตรวจ Payroll ของสาขา

1. เปิด **เงินเดือน**.
2. เลือกร้านที่ครอบคลุมสาขาของตน แล้วกด **เปิดสมุดงาน**.
3. เลือกรอบเงินเดือน.
4. ตรวจรายการพนักงาน ยอดรายได้ รายการหัก ยอดสุทธิ และหลักฐานคำนวณ.

Branch Manager เป็นสิทธิ์อ่านเฉพาะสาขา จึงไม่ควรเห็นปุ่มสร้าง configuration,
เปิดรอบ, preview, lock หรือ Adjustment และต้องไม่เห็น payroll record ของสาขาอื่น

### 5.4 ข้อจำกัดของ Branch Manager

- ไม่จัดการ Accounts, Organization, Finance, Payslips, Reports หรือ Audit.
- ไม่ล็อกรอบเงินเดือน.
- หน้า Schedule/Holiday management ยังไม่ถูกเปิดในเมนู แม้ backend มี API.

## 6. คู่มือ HR

HR เป็นผู้ดูแลข้อมูลพนักงานและกระบวนการเงินเดือนทุกสาขา แต่ไม่มีหน้า
**ตั้งค่าพร้อมใช้งาน** ซึ่งสงวนให้ Owner

### 6.1 จัดการบัญชีผู้ใช้

1. เปิด **บัญชีผู้ใช้**.
2. ค้นหาด้วยชื่อผู้ใช้หรือสถานะ.
3. กด **สร้างบัญชี** เพื่อสร้างบัญชีใหม่และเชื่อม employee ID หากมี.
4. จดรหัสผ่านชั่วคราวทันที เพราะแสดงครั้งเดียว.
5. เปิดรายละเอียดบัญชีเพื่อ:
   - ดูบทบาทและขอบเขต.
   - เพิ่มหรือถอน role grant.
   - เปิด/ปิดใช้งานบัญชี.
   - ปลดล็อกบัญชี.
   - รีเซ็ตรหัสผ่านและรับรหัสชั่วคราวใหม่.
6. ทุก mutation ต้องกรอกเหตุผลเมื่อหน้าจอกำหนด.

HR จัดการ Employee, Supervisor, Branch Manager และ HR grants ได้ แต่การให้หรือ
ถอน Owner role ต้องทำโดย Owner และระบบต้องป้องกันการนำ Owner คนสุดท้ายออก

### 6.2 จัดการโครงสร้างองค์กร

1. เปิด **โครงสร้างองค์กร**.
2. เลือกประเภท Shop, Branch, Department หรือ Position.
3. ใช้ตัวกรองสถานะและ parent organization เพื่อค้นหา.
4. กดเพิ่มรายการ กรอกรหัส ชื่อ และ parent ที่เกี่ยวข้อง.
5. หากเลิกใช้ master data ให้เลือก **ปิดใช้งาน** และระบุเหตุผล ห้ามลบข้อมูลที่
   อาจถูกอ้างอิงจากประวัติ.

### 6.3 รับพนักงานใหม่

1. เปิด **พนักงาน** แล้วกด **รับพนักงานใหม่**.
2. กรอกข้อมูลพนักงานและเอกสารยืนยันตัวตนอย่างน้อยหนึ่งประเภท.
3. กรอก assignment แรก: ร้าน สาขา แผนก ตำแหน่ง ประเภทการจ้าง เงินเดือนฐาน
   สวัสดิการ และวันที่เริ่มมีผล.
4. เพิ่มบัญชีธนาคาร วันหยุดประจำสัปดาห์ หรือบัญชีผู้ใช้หากต้องการ.
5. ส่งแบบฟอร์มครั้งเดียว ระบบบันทึก onboarding ทั้งชุดใน transaction เดียว.
6. หากขั้นตอนใดผิดพลาด ต้องไม่เหลือพนักงานที่สร้างค้างบางส่วน.

### 6.4 จัดการประวัติพนักงาน

จากหน้ารายละเอียดพนักงาน HR สามารถ:

- เพิ่มช่วง assignment ใหม่สำหรับย้ายสาขา เปลี่ยนแผนก เลื่อนตำแหน่ง หรือปรับ
  เงินเดือน/สวัสดิการ โดยระบบต้องปิดช่วงเดิมก่อนเริ่มช่วงใหม่.
- เพิ่ม แก้ ปิดใช้งาน และเปลี่ยนบัญชีธนาคารหลัก โดยเลขบัญชีตอบกลับแบบปกปิด.
- เพิ่มหรือสิ้นสุดช่วงวันหยุดประจำสัปดาห์.
- เปลี่ยนสถานะการจ้างโดยไม่ลบประวัติ.

ห้ามแก้ค่าของ assignment เก่าให้เหมือนเป็นข้อมูลใหม่ เพราะ Payroll และ
Attendance ต้องอ้างอิงข้อเท็จจริงตามวันที่

### 6.5 จัดการ Attendance, Leave และ OT

HR ใช้ขั้นตอนเดียวกับ Supervisor/Branch Manager แต่เลือกพนักงานได้ทุกสาขา
ก่อนอนุมัติให้ตรวจ scope, วันที่, ประเภท, เอกสารที่ต้องใช้ และสถานะรอบเงินเดือน

### 6.6 จัดการ Finance

1. เปิด **เงินทดรองและหนี้**.
2. เลือกพนักงาน แล้วกด **โหลดข้อมูลการเงิน**.

เงินทดรองจ่าย:

1. กรอกจำนวนเงินและส่งคำขอ.
2. ก่อนอนุมัติ ตรวจว่าวันที่ขอถึงเกณฑ์, วันทำงานครบ, จำนวนไม่เกินเพดาน
   เงินเดือน และยอดสุทธิไม่ติดลบ.
3. กด **อนุมัติ** หรือ **ไม่อนุมัติ** เฉพาะรายการรอพิจารณา.

เงินกู้:

1. กรอกเงินต้น จำนวนงวด 1–5 งวด เดือนเริ่มชำระ และเหตุผล.
2. กด **สร้างเงินกู้**.
3. ตรวจตาราง installment และยอดคงเหลือก่อนปิดรอบเงินเดือน.

บัญชีหนี้:

1. ระบุประเภทหนี้ ประเภทรายการ จำนวนเงิน และรายละเอียด.
2. กด **บันทึกรายการ**.
3. หากรายการยังไม่ถูก settle และบันทึกผิด ให้ใช้ **กลับรายการ** พร้อมเหตุผล.
4. ห้ามลบหรือ reset ledger เพราะประวัติหนี้ต้องตรวจสอบย้อนหลังได้.

ข้อควรระวัง: ช่องประเภทหนี้ปัจจุบันยังต้องกรอก raw ID จนกว่า T021 จะเสร็จ

### 6.7 เปิดและปิดรอบเงินเดือน

1. เปิด **เงินเดือน**.
2. เลือกร้าน แล้วกด **เปิดสมุดงาน**.
3. ตรวจ **ความพร้อมของค่าคำนวณ** และสร้าง configuration ที่ยังขาด เช่น
   จำนวนวันทำงาน อัตราหักขาด/สาย OT และประกันสังคม.
4. เลือกเดือนและกดสร้างรอบใหม่.
5. เลือกรอบ แล้วกด **คำนวณตัวอย่าง**.
6. ตรวจ blocker และแก้ข้อมูลต้นทาง:
   - Attendance ไม่ครบ.
   - Leave/OT/Advance/Adjustment ยังรอพิจารณา.
   - Assignment หรือ configuration ไม่ครอบคลุมวันที่.
   - ยอดสุทธิติดลบ.
7. ตรวจรายได้ รายการหัก ยอดสุทธิ และกดดูรายการหลักฐานของแต่ละพนักงาน.
8. เมื่อถูกต้อง กด **ล็อกรอบ** และยืนยัน.

หลังล็อก:

- ห้ามแก้ Attendance, approval หรือค่าคำนวณที่ใช้กับรอบนั้น.
- หากพบข้อผิดพลาด ให้ส่ง Adjustment ไปยังรอบเป้าหมาย.
- หน้าเว็บปัจจุบันส่งคำขอ Adjustment ได้ แต่หน้ารายการและอนุมัติ/ปฏิเสธยังไม่
  เสร็จ ต้องดำเนินการหลัง T018.

### 6.8 ออกและจัดส่งสลิปเงินเดือน

1. เปิด **สลิปเงินเดือน**.
2. ใช้ payroll record จากรอบที่ล็อกแล้ว กรอก ID และกด **ออกสลิป**.
3. ระบบต้องปฏิเสธการออกสลิปซ้ำสำหรับ payroll record เดิม.
4. เปิดสลิปเดิมด้วย Payslip ID.
5. กรอกอีเมลและกด **บันทึกการส่ง**.
6. ตรวจประวัติการส่งแต่ละครั้ง.
7. หากสลิปใช้ไม่ได้ ให้กด **ยกเลิกสลิป**; ประวัติเดิมต้องยังอยู่.

การส่งใน baseline เป็น mock delivery log การขึ้นสถานะสำเร็จหมายถึงระบบบันทึก
attempt แล้ว ไม่ควรตีความว่าอีเมลจริงถึงผู้รับจนกว่าจะเชื่อม mail provider

### 6.9 ส่งออกรายงาน

1. เปิด **รายงาน**.
2. กรอก Payroll Period ID ของรอบที่ล็อกแล้ว.
3. เลือก:
   - **ไฟล์โอนเงินธนาคาร (CSV)**.
   - **รายงานประกันสังคม (CSV)**.
4. ตรวจชื่อพนักงาน บัญชี ยอดโอน และผลรวมก่อนส่งต่อ.
5. ประกันสังคมต้องคำนวณจาก base salary เท่านั้น ไม่รวม welfare.

หน้ารายงานเชิงบริหาร Attendance/Leave/OT/Debt/Payroll ยังไม่เปิดใช้งาน

### 6.10 ตรวจ Audit

1. เปิด **ประวัติการเปลี่ยนแปลง**.
2. กรองด้วย action, ชื่อตาราง, record ID, actor account, ช่วงเวลา หรือ Request ID.
3. กด **ค้นหาประวัติ**.
4. ตรวจผู้ดำเนินการ เวลา เหตุผล และ target.
5. เปิด **ข้อมูลเดิม** หรือ **ข้อมูลใหม่** เมื่อจำเป็น.

ข้อมูลลับ เช่น password, token, identity number เต็ม และเลขบัญชีเต็ม ต้องไม่
ปรากฏใน Audit หากพบให้หยุดเผยแพร่ log และแจ้ง Owner ทันที

## 7. คู่มือ Owner

Owner ใช้ฟังก์ชันทั้งหมดของ HR และมีหน้าที่เพิ่มดังนี้

### 7.1 ตั้งค่าระบบครั้งแรก

1. เปิด **การตั้งค่า**.
2. เพิ่ม **ร้าน** ด้วยรหัสและชื่อที่ไม่ซ้ำ.
3. เลือกร้านแล้วเพิ่ม **สาขา**.
4. สร้าง **บัญชีผู้ใช้** และจดรหัสผ่านชั่วคราวทันที.
5. กำหนด **บทบาทและขอบเขต**:
   - Employee: self และควรเชื่อม employee record.
   - Supervisor: department พร้อม branch/department ที่ตรงกัน.
   - Branch Manager: branch.
   - HR: all.
   - Owner: all และจัดการผ่านหน้า Accounts โดย Owner เท่านั้น.
6. ไปที่ **โครงสร้างองค์กร** เพื่อเพิ่ม Department และ Position.
7. ไปที่ **พนักงาน** เพื่อ onboarding และกำหนด assignment.
8. ไปที่ **เงินเดือน** เพื่อสร้าง configuration และรอบเงินเดือน.

### 7.2 ดูแลสิทธิ์ Owner

- Owner เท่านั้นที่ให้หรือถอน Owner role ได้.
- ห้ามปิดบัญชีหรือถอน grant ที่ทำให้ไม่เหลือ active Owner.
- ตรวจเหตุผลและ Audit ทุกครั้งหลังเปลี่ยนสิทธิ์ระดับสูง.
- อย่าใช้บัญชี Owner ทำงานประจำวันหาก HR สามารถทำได้.

### 7.3 ตรวจสอบก่อนอนุมัติการใช้งานจริง

- บัญชีทุกคนเชื่อม employee และ scope ถูกต้อง.
- Supervisor เห็นเฉพาะแผนก; Branch Manager เห็นเฉพาะสาขา.
- HR/Owner เห็นทุกสาขาแต่ Employee เห็นเฉพาะตนเอง.
- Payroll configuration ครอบคลุมวันที่และไม่มี effective range ซ้อน.
- รอบที่ล็อกแล้วแก้ย้อนหลังไม่ได้.
- สลิปของพนักงานอื่นถูกปฏิเสธ.
- Audit ไม่เก็บข้อมูลลับ.
- Backup ล่าสุดสามารถ restore ได้จริง.

## 8. ขั้นตอนงานประจำรอบเงินเดือน

### ระหว่างเดือน

1. Supervisor/Branch Manager/HR บันทึกและแก้ Attendance ก่อนล็อกรอบ.
2. Employee ส่ง Leave/OT; ผู้มีสิทธิ์พิจารณาให้หมด.
3. HR บันทึก Advance, Loan และ Debt ตามหลักฐาน.
4. HR ตรวจ assignment, salary, welfare, bank account และ weekly holiday ที่มีผล.

### ก่อนล็อกรอบ

1. HR เปิด Payroll และรัน preview.
2. แก้ Attendance ที่ขาดและจัดการ pending approvals.
3. ตรวจ negative net pay และข้อมูล configuration.
4. เทียบยอดรายได้/หักกับหลักฐานรายคน.
5. รัน preview ซ้ำจนไม่มี blocker.

### หลังล็อกรอบ

1. ห้ามแก้ข้อมูล snapshot เดิม.
2. สร้างและอนุมัติ Adjustment เมื่อมี correction.
3. ออก Payslip หนึ่งรายการต่อ payroll record.
4. บันทึก delivery attempt.
5. ส่งออก Bank Transfer และ Social Security CSV.
6. ใช้ Audit ตรวจรายการสำคัญด้วย Request ID.

## 9. ฟังก์ชันที่ยังไม่เปิดใช้งานหรือยังไม่สมบูรณ์

รายการต่อไปนี้ถูกติดตามใน
`specs/012-system-completion/tasks.md` และไม่ควรสอนผู้ใช้ว่าใช้งานได้แล้ว:

- Employee self-service สำหรับเงินทดรอง.
- หน้า Schedule, date override และ public holiday แม้ backend มี API.
- การแสดง Leave/OT approval history ในหน้าเว็บ.
- รายการและการอนุมัติ Payroll Adjustment.
- การแนบ/ดาวน์โหลดเอกสารพนักงานและเอกสารลา.
- รายละเอียด/ดาวน์โหลดสลิปสำหรับ Employee.
- Management reports นอกเหนือจาก CSV สองชนิด.
- การส่งอีเมลจริง; ปัจจุบันเป็น mock delivery log.
- การเปลี่ยนรหัสผ่านด้วยตนเอง.
- ตัวเลือกชื่อแทน raw IDs ในบางหน้า.

## 10. ข้อมูลที่ควรส่งให้ผู้ดูแลเมื่อขอความช่วยเหลือ

ส่งเฉพาะข้อมูลต่อไปนี้:

- ชื่อหน้าและ action ที่ทำ.
- วันและเวลาที่เกิดปัญหา.
- ข้อความ error และ Request ID.
- บทบาทและสาขา/แผนกของบัญชี.
- Record ID ที่ไม่เป็นความลับ ถ้ามี.

ห้ามส่งรหัสผ่าน, token, session cookie, เลขบัตรประชาชนเต็ม หรือเลขบัญชีธนาคาร
