# ข้อมูลสำหรับพรีเซนต์ Haris Payroll

เมื่อเริ่มระบบพัฒนาด้วย `docker compose up -d --build` ระบบสร้างร้าน **Haris** พร้อมสาขารามอินทรา ปากเกร็ด และนนทบุรี สาขาละ 20 คน (รวม 60 คน) หากยังไม่มีข้อมูลชุดนี้ ข้อมูลบุคคล หมายเลขโทรศัพท์ บัญชีธนาคาร และอีเมลเป็นข้อมูลสมมติสำหรับสาธิต ห้ามใช้จ่ายเงินจริง

| บทบาท | ชื่อผู้ใช้ | รหัสผ่านเริ่มต้น |
| --- | --- | --- |
| เจ้าของร้าน | `haris_owner` | `HarisDemo2026!` |
| HR / บัญชี | `haris_hr` | `HarisDemo2026!` |
| ผู้จัดการสาขารามอินทรา | `haris_manager` | `HarisDemo2026!` |
| หัวหน้าแผนกสาขารามอินทรา | `haris_supervisor` | `HarisDemo2026!` |
| พนักงาน ณัฐชา วัฒนกุล | `haris_employee` | `HarisDemo2026!` |

เลือก **ร้าน Haris** ที่หน้าเงินเดือน จะพบรอบของเดือนก่อนหน้าที่เตรียมข้อมูลการจ้าง ตารางสาขา ค่าคำนวณ และเวลาเข้างานไว้สำหรับคำนวณและล็อก เมื่อใช้สิทธิ์ผู้จัดการสาขา ให้เลือกรายการ OT ของ ณัฐชา ในเดือนปัจจุบันเพื่อทดลองพิจารณา

สำหรับสาธิตการปิดรอบโดยแยกจากฐานเดิม ให้เริ่มระบบด้วยคำสั่งนี้จากโฟลเดอร์หลัก:

```bash
HTTP_PORT=18087 POSTGRES_PORT=55487 docker compose --env-file /dev/null -p haris-payroll-presentation up -d --build
```

เปิด [เว็บชุดพรีเซนต์](http://localhost:18087/login) ด้วยบัญชี `haris_hr` จากนั้นไปที่ **เงินเดือน → Haris → เปิดสมุดงาน → งวดเดือนก่อน → คำนวณตัวอย่าง → ล็อกรอบ** พนักงานทั้ง 60 คนมีเวลาเข้า 09:00 และออก 18:00 ครบทุกวันทำงานในงวด ส่วนวันอาทิตย์เป็นวันหยุดประจำสัปดาห์ เก็บปุ่ม **ล็อกรอบ** ไว้กดตอนพรีเซนต์ เพราะเมื่อยืนยันแล้วงวดจะถูกล็อกจริงในฐานสาธิต

ข้อมูลนี้เตรียมบัญชีและข้อมูลพื้นฐานให้ทดลอง use case ผ่านหน้าเว็บ ไม่ได้หมายความว่าทุกสถานการณ์ผ่านการทดสอบแล้ว คำขอเงินทดรองยังต้องผ่านเงื่อนไขวันที่ 20 จำนวนวันทำงาน และเงื่อนไขอื่นของระบบ อีเมลตัวอย่างใช้ `example.test` และไม่ใช่ที่อยู่อีเมลจริง

หากไม่ได้ตั้งค่า SMTP เอง Docker โหมดพัฒนาจะส่งอีเมลไปยัง Mailpit ภายในเครื่อง เปิดกล่องรับได้โดยรัน `docker compose port mailpit 8025` แล้วนำที่อยู่ที่แสดงไปเปิดในเบราว์เซอร์ Mailpit เป็นกล่องจำลอง ไม่ส่งอีเมลออกภายนอก

การเริ่มระบบครั้งถัดไปจะเก็บข้อมูลเดิม ไม่ย้อนสถานะรอบหรือรหัสผ่าน และไม่สร้างชุดข้อมูลซ้ำ หากต้องการชุดเริ่มต้นอีกครั้ง ให้ใช้ฐานข้อมูลพัฒนาใหม่แยกต่างหาก ห้ามลบ volume ฐานข้อมูลเดิมโดยไม่ได้สำรองข้อมูล การ seed อัตโนมัติใช้เฉพาะ Docker สำหรับการพัฒนา ส่วน production ไม่เรียก seed นี้
